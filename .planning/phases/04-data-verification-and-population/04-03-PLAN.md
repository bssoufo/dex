  <action>
  Create `backend/src/etl/verify/apply.py` -- a script that applies all verification fixes and metadata to the 19 JSON files.

  The script does these operations IN ORDER:

  **Step 1: Fix confirmed errors**

  a) Voltage fixes (Jetsetter LX and Prodigy):
     - Both models have spa_pak.voltage=115 but top-level voltage=240 and heater.voltage=240
     - The 115V is the spa_pak's secondary/accessory voltage, not the primary input voltage
     - Fix: Set spa_pak.voltage to 240 for both models (matching the primary electrical spec)
     - Record in data_quality.anomalies_reviewed with status="fixed"

  b) Cover dimension fixes (M6 and M9):
     - M6: cover L=91, W=80 but spa dims L=80, W=91 -- swap cover to L=80, W=91
     - M9: cover L=110, W=94 but spa dims L=94, W=110 -- swap cover to L=94, W=110
     - The cover should match the spa's physical dimensions (cover sits on top)
     - Record in data_quality.anomalies_reviewed with status="fixed"

  **Step 2: Add data_quality metadata to every model**

  For each of the 19 models:
  ```python
  data_quality = {
      "verification_date": "2026-02-16",
      "verified_by": "automated_checks_v1",
      "not_available_fields": build_not_available_list(model),
      "anomalies_reviewed": [...],  # populated per-model
      "completeness_pct": compute_model_completeness(model)
  }
  ```

  The `anomalies_reviewed` list contains entries for known issues:
  - For the 6 jet count mismatches (Envoy, Grandee, Jetsetter, Altamar, Aspen, Cameo):
    ```python
    {
        "field": "jets.total_jet_count vs jets.jets_by_type sum",
        "issue": f"total={total} vs sum_by_type={sum_val}",
        "resolution": "Different counting methods: total is primary therapy jets, by_type includes all jet types including water features",
        "status": "accepted"
    }
    ```
  - For the 2 missing categories (Marin filters=NULL, Jetsetter LX lighting=NULL):
    ```python
    {
        "field": "filters" or "lighting",
        "issue": "Category entirely null -- extraction failed",
        "resolution": "Data not extractable from available sources",
        "status": "accepted_not_available"
    }
    ```
  - For the 6 empty Bullfrog categories:
    ```python
    {
        "field": "heater" or "spa_pak",
        "issue": "Category present but all fields null",
        "resolution": "Bullfrog manuals do not include this specification",
        "status": "accepted_not_available"
    }
    ```

  **Step 3: Mark source references as verified**

  For each source_documents entry on each model:
  ```python
  source.verified_by = "automated_checks_v1"
  source.verified_date = "2026-02-16"
  ```

  **Step 4: Compute completeness percentage**

  `completeness_pct` = (non-null meaningful fields - not_available_fields) / (total meaningful fields - not_available_fields) * 100

  This gives the completeness of AVAILABLE data, excluding fields that genuinely do not exist in sources.

  **Step 5: Write updated JSON files**

  For each model:
  1. Load the JSON file
  2. Apply fixes
  3. Add data_quality
  4. Update source references
  5. Validate with SpaModel.model_validate()
  6. Write back with json.dumps(indent=2) + trailing newline
  7. Validate again after writing (round-trip check)

  Then run the apply script:

  IMPORTANT: Use the same JSON serialization format as existing files (2-space indent, no trailing comma, UTF-8). Do NOT change field ordering beyond adding the new data_quality section.

  IMPORTANT: The anomalies_reviewed entries for jet count mismatches use status="accepted" (not "fixed") because the values are NOT changed -- both numbers may be correct depending on counting method. The resolution explains why.

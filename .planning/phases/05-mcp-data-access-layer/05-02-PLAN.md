       **IMPORTANT: FastMCP Client.call_tool() returns a list of content blocks, not a dict directly.**
       The first element is typically a TextContent with `.text` containing JSON. Create a helper:
       ```python
       def parse_result(result) -> dict:
           """Extract dict from FastMCP Client call_tool response."""
           # result is a list of content blocks; first block .text is JSON string
           if isinstance(result, dict):
               return result
           if isinstance(result, list) and len(result) > 0:
               text = result[0].text if hasattr(result[0], 'text') else str(result[0])
               return json.loads(text)
           return json.loads(str(result))
       ```
       Use `parse_result()` on every `client.call_tool()` return value. If FastMCP 2.14 returns dicts directly, the isinstance check handles that gracefully too.

       Note: With Literal type constraints, FastMCP may reject invalid model names at the protocol level before the function runs. The test should handle both cases:

       - If the function handles it internally, assert success=False with message

       Create a test `test_not_found_handling_documented(client)` that simply documents this behavior:
       ```python
       async def test_not_found_handling_documented(client):
           """Document: FastMCP Literal types reject invalid model names at protocol level.
           Invalid manufacturer/model combinations that pass Literal validation but don't
           exist in the data store are handled by the tool returning success=False."""
           # Test a valid manufacturer + valid model name that are mismatched
           # e.g., Sundance manufacturer + Bullfrog model name
           result = parse_result(await client.call_tool(
               "get_spec_category",
               {"manufacturer": "sundance", "model_name": "M9", "category": "jet_pumps"},
           ))
           assert result["success"] is False
           assert "not found" in result["message"].lower()
       ```

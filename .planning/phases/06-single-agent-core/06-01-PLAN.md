3. Create `backend/src/agent/prompts.py` with SYSTEM_PROMPT string containing:

   **Identity section:**
   - Name is Dex, a technical knowledge assistant for Spaparts
   - Covers 19 spa models across 3 manufacturers
   - Lists the exact manufacturer-model mapping for disambiguation:
     - Sundance (880 Series): Altamar, Aspen, Cameo, Capris, Marin, Optima, Vistamar
     - Hot Spring (Highlife Collection): Aria, Envoy, Grandee, Jetsetter, Jetsetter LX, Prodigy, Sovereign, Vanguard
     - Bullfrog (M Series): M6, M7, M8, M9

   **Critical rules section (numbered 1-5):**
   1. NEVER fabricate data. If a tool returns null or "not available" for a field, say "This information is not available in our records." Do NOT guess or infer.
   2. ALWAYS use tools to answer. Never answer from memory or general knowledge. Every spec value must come from a tool call.
   3. Use list_models first if unsure which manufacturer a model belongs to.
   4. Use get_model_overview to check available categories before querying specifics.
   5. Use get_spec_category for detailed specs (jet_pumps, circulation_pump, spa_pak, topside_control, jets, headrests, filters, heater, lighting, cover).

   **Not-available handling section:**
   - When a field value is null, check the not_available_fields list in the response
   - If field is in not_available_fields: say "not available from manufacturer documentation"
   - If field is null but NOT in not_available_fields: say "data not yet extracted"

   **Out-of-scope handling section:**
   - Models outside 19 POC: list what you cover, say you don't have the requested model
   - Pricing/availability/non-technical: say you specialize in technical specifications only
   - Ambiguous queries without model: ask which model the user means

   **Response format section:**
   - Lead with direct answer (part number, spec value)
   - Include relevant details (HP, wattage, compatibility)
   - Flag not-available fields explicitly
   - Be concise and professional -- no filler
  </action>

1. Create `backend/src/agent/graph.py`:

   - Import ChatGoogleGenerativeAI from langchain_google_genai
   - Import MultiServerMCPClient from langchain_mcp_adapters.client
   - Import create_react_agent from langgraph.prebuilt
   - Import SYSTEM_PROMPT from backend.src.agent.prompts
   - Use load_dotenv(dotenv_path="backend/.env") at module level to load GEMINI_API_KEY

   Create `_create_model()` function:
   - Returns ChatGoogleGenerativeAI with model="gemini-2.5-flash", temperature=0, max_output_tokens=1024
   - Uses os.getenv("GEMINI_API_KEY") for google_api_key parameter

   Create `_create_mcp_client()` function:
   - Returns MultiServerMCPClient configured with "dex_data" server
   - Command: "python", args: ["-m", "backend.src.mcp"], transport: "stdio"
   - NOTE: The command must work from the project root (where PYTHONPATH=. is set)
   - On Windows, use "python" not "python3"

   Create `async def create_dex_agent()`:
   - Instantiates MCP client via _create_mcp_client()
   - Loads tools via `await client.get_tools()`
   - Creates model via _create_model()
   - Creates ReAct agent via create_react_agent(model=model, tools=tools, prompt=SYSTEM_PROMPT)
   - Returns tuple of (agent, client) -- caller is responsible for closing client
   - Docstring explains caller must close client

   Use standard pytest conventions. Mark no tests as integration (all unit-level).

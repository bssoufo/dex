<task type="auto">
  <name>Task 1: Production-harden the FastAPI app</name>
  <files>
    backend/src/api/app.py
    frontend/src/services/api.ts
    frontend/.env.production
  </files>
  <action>
    Modify backend/src/api/app.py to add three production capabilities:

    1. **Global exception handler** -- Add an `@app.exception_handler(Exception)` that catches all unhandled exceptions, logs the full traceback via `logging.getLogger(__name__)`, and returns a JSON response `{"detail": "An internal error occurred. Please try again.", "type": "<ExceptionClassName>"}` with status 500. Import `logging`, `Request` from fastapi, and `JSONResponse` from fastapi.responses.

    2. **Environment-aware CORS** -- Read `ENVIRONMENT` from `os.getenv("ENVIRONMENT", "development")`. In production, set `allow_origins` to `[os.getenv("ALLOWED_ORIGIN", "*")]`. In development, keep the current localhost origins list (`["http://localhost:5173", "http://localhost:4173"]`). Import `os` at top of file.

    3. **Static file serving + SPA catch-all** -- At the BOTTOM of app.py (after all API route definitions), add conditional static file serving. Compute `FRONTEND_DIR = Path(__file__).resolve().parent.parent.parent.parent / "frontend" / "dist"`. If `FRONTEND_DIR.exists()`, mount `StaticFiles(directory=FRONTEND_DIR / "assets")` at `/assets`. Then add a catch-all `@app.get("/{path:path}")` route that: (a) checks if `FRONTEND_DIR / path` is a file and `".." not in path`, returns `FileResponse(file_path)` if so; (b) otherwise returns `FileResponse(FRONTEND_DIR / "index.html")`. Import `Path` from pathlib, `StaticFiles` from fastapi.staticfiles, `FileResponse` from fastapi.responses.

    IMPORTANT: The SPA catch-all MUST be defined AFTER all other routes. FastAPI evaluates routes in order, so `/health`, `/query`, and `/query/stream` must be defined before the catch-all.

    Also modify frontend/src/services/api.ts:
    - Change `export const API_BASE = "/api";` to `export const API_BASE = import.meta.env.VITE_API_BASE ?? "/api";`
    This allows the production build to use an empty string (direct paths) while dev still uses "/api" (proxied by Vite).

    Create frontend/.env.production with content:
    ```
    VITE_API_BASE=
    ```
    Vite automatically loads .env.production during `npm run build`. The empty value makes API_BASE resolve to "" via the ?? operator, so production calls go to `/query/stream` directly (same origin, no proxy needed).
  </action>

    All non-integration tests must pass. The health endpoint, query endpoint, and streaming endpoint tests should still work since the static file serving is conditional (FRONTEND_DIR won't exist during tests).
  </verify>

    Note: Do NOT exclude *.md globally (README might matter), but .planning/ covers all planning docs. Do NOT exclude backend/src/data/ -- it contains the 19 JSON files needed at runtime.

    Create Dockerfile at project root with a 3-stage multi-stage build:

    **Stage 1: frontend-builder** (FROM node:22-alpine)
    - WORKDIR /frontend
    - COPY frontend/package.json frontend/package-lock.json ./
    - RUN npm ci
    - COPY frontend/ ./
    - RUN npm run build

    **Stage 2: backend-builder** (FROM python:3.12-slim)
    - COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/
    - WORKDIR /app
    - ENV UV_COMPILE_BYTECODE=1 UV_LINK_MODE=copy
    - COPY backend/pyproject.toml backend/uv.lock ./backend/
    - RUN --mount=type=cache,target=/root/.cache/uv cd backend && uv sync --locked --no-install-project --no-dev
    - COPY backend/ ./backend/
    - RUN --mount=type=cache,target=/root/.cache/uv cd backend && uv sync --locked --no-dev

    **Stage 3: runtime** (FROM python:3.12-slim)
    - WORKDIR /app
    - COPY --from=backend-builder /app/backend/.venv /app/backend/.venv
    - COPY --from=backend-builder /app/backend/src /app/backend/src
    - COPY --from=frontend-builder /frontend/dist /app/frontend/dist
    - ENV PATH="/app/backend/.venv/bin:$PATH"
    - ENV PYTHONPATH="/app"
    - EXPOSE 8000
    - CMD using shell form (not exec form) so $PORT expands: `CMD uvicorn backend.src.api.app:app --host 0.0.0.0 --port ${PORT:-8000}`

    IMPORTANT: Use shell form for CMD (not JSON array) so the ${PORT:-8000} variable expansion works. Railway sets PORT dynamically.

    Verify the build works locally:
    ```
    docker build -t dex:local .
    ```
    Then test the container starts and serves both frontend and API:
    ```
    docker run --rm -p 8080:8000 -e GEMINI_API_KEY=$(cat backend/.env | grep GEMINI_API_KEY | cut -d= -f2) dex:local
    ```
    In a separate terminal, verify:
    - `curl http://localhost:8080/health` returns `{"status":"ok","agent_ready":true}`
    - `curl http://localhost:8080/` returns HTML (the React index.html)

    Stop the container after verification.
  </action>

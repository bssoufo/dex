<objective>
Build the multi-agent supervisor graph with Concierge, Specialist, and deterministic Validator.

Purpose: Transform the Phase 6 single ReAct agent into a Concierge/Specialist/Validator pipeline using langgraph-supervisor. The Specialist retains all MCP tools. The Concierge handles disambiguation. The Validator is a deterministic Python function (no LLM call) that checks response quality. InMemorySaver checkpointer enables multi-turn conversation via thread_id.

Output: New agent architecture files (config.py, prompts.py rewrite, validator.py, graph.py rewrite) plus updated unit tests.
</objective>

3. Rewrite `backend/src/agent/prompts.py` -- replace the single SYSTEM_PROMPT with three prompts:

   **SUPERVISOR_PROMPT**: Route user queries to the right agent.
   - Route to `concierge` ONLY when the query is genuinely ambiguous (user mentions "the pump" without specifying a model, asks about a category without specifying a model, follow-up lacks context not in history).
   - Route to `specialist` for ALL clear queries where model and category are identifiable.
   - IMPORTANT: Most queries should go directly to specialist. Only use concierge for genuinely ambiguous queries.

   **CONCIERGE_PROMPT**: Clarify ambiguous queries only.
   - Identity: "You are the Dex Concierge."
   - Job: Identify what's missing (model name, manufacturer, spec category) and ask a focused clarification question.
   - Can use list_models tool to help user identify their model.
   - Lists all 19 models across 3 manufacturers (same mapping as current SYSTEM_PROMPT).
   - NEVER answer spec questions. NEVER fabricate data. Only output is a clarification question or a restated clear query.

   **SPECIALIST_PROMPT**: Answer spec questions using tools (the current SYSTEM_PROMPT, largely unchanged).
   - Keep the existing CRITICAL RULES (NEVER fabricate, ALWAYS use tools, use list_models, use get_model_overview, use get_spec_category).
   - Keep NOT-AVAILABLE FIELD HANDLING section.
   - Keep RESPONSE FORMAT section.
   - Remove the OUT-OF-SCOPE HANDLING section about asking which model (that's now the Concierge's job). Keep the out-of-scope model refusal and pricing refusal in the Specialist since the Specialist may still encounter these.

4. Create `backend/src/agent/validator.py` -- deterministic validation (NO LLM call):
   - `validate_response(state: dict) -> dict`: Inspects the Specialist's output.
   - Checks: (a) At least one tool call message exists in state["messages"] -- if not, warning "No tool calls detected -- response may be fabricated". (b) Last AI message content is >20 chars -- if not, warning "Response too short". (c) Last AI message does not contain the literal word "null" as a standalone word (regex `\bnull\b`) -- if found, warning "Response contains literal 'null'".
   - Returns `{"validation_warnings": warnings_list}` where warnings_list is a `list[str]`.
   - This is a plain Python function, NOT an LLM agent. No imports from langchain/langgraph.

   - Import `create_react_agent` from `langgraph.prebuilt`.
   - Import `InMemorySaver` from `langgraph.checkpoint.memory`.

   Create `async def create_multi_agent(mcp_tools=None)`:
   - If mcp_tools is None, create MCP client via `create_mcp_client()` and call `await client.get_tools()`.
   - Create model via `create_model()`.
   - Create concierge agent: `create_react_agent(model=model, tools=[list_models_tool], name="concierge", prompt=CONCIERGE_PROMPT)` where list_models_tool is the tool from mcp_tools whose name is "list_models". If no list_models tool found, pass the full mcp_tools list as fallback (safety net for tests).
   - IMPORTANT: Gemini may error with empty tools. Concierge MUST have at least one tool (list_models).
   - Create specialist agent: `create_react_agent(model=model, tools=mcp_tools, name="specialist", prompt=SPECIALIST_PROMPT)`.
   - Create supervisor: `create_supervisor(agents=[concierge, specialist], model=model, prompt=SUPERVISOR_PROMPT, include_agent_name="inline", output_mode="last_message")`.
   - CRITICAL: `include_agent_name="inline"` is required for Gemini compatibility (Gemini does not support the name attribute on AI messages).
   - Create checkpointer: `InMemorySaver()`.
   - Compile: `app = workflow.compile(checkpointer=checkpointer)`.
   - Return `(app, client_if_created)` -- return the MCP client only if this function created it (so caller can manage lifecycle). If mcp_tools were passed in, return None for client.

   Also keep the old `create_dex_agent` as a thin wrapper that calls `create_multi_agent()` for backward compatibility during migration. Mark with a deprecation comment.

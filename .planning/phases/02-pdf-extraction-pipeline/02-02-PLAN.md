  <action>
    Create the core Claude PDF extraction module at `backend/src/etl/extract/claude_extractor.py`.

    Define a Pydantic model for the raw extraction result:
    ```python
    class CategoryExtraction(BaseModel):
        """Raw extraction result for a single spec category from Claude."""
        model_name: str
        spec_category: str
        page_numbers: list[int] = Field(description="Page numbers where data was found")
        section_title: str | None = None
        confidence: Literal["high", "medium", "low"]
        notes: str | None = None
        data: dict  # Raw extracted spec data, varies by category
    ```

    Implement two functions:

    1. `extract_spec_category(pdf_path: Path, extraction_prompt: str, model: str = None) -> CategoryExtraction`:
       - Reads PDF file and base64 encodes it
       - Creates anthropic.Anthropic() client
       - Calls `client.messages.create()` with:
         - model: `model` param or `CLAUDE_MODEL` from config
         - max_tokens: `MAX_TOKENS` from config
         - messages: single user message with two content blocks:
           a. `type: "document"` with base64 PDF data, `media_type: "application/pdf"`, and `cache_control: {"type": "ephemeral"}` (critical for cost -- caches the PDF across calls)
           b. `type: "text"` with the extraction_prompt
         - output_config: `{"format": {"type": "json_schema", "schema": transform_schema(CategoryExtraction)}}`
           Use `from anthropic import transform_schema`
       - Parses response: `CategoryExtraction.model_validate_json(response.content[0].text)`
       - Returns the CategoryExtraction instance
       - Wraps API errors in a clear exception with context (which PDF, which category)

    2. `extract_model_specs(pdf_path: Path, template: ManufacturerTemplate, model_name: str) -> dict[str, CategoryExtraction]`:
       - Iterates over `SPEC_CATEGORIES` from config
       - For each category, calls `template.get_extraction_prompt(model_name, category)` to get the prompt
       - Calls `extract_spec_category()` for each
       - Returns dict mapping category name to CategoryExtraction
       - Prints progress: `"Extracting {model_name} / {category}... ({confidence})"`
       - If any extraction fails (API error), logs the error and continues with remaining categories (does not abort the whole model)

    IMPORTANT design decisions:
    - Use `anthropic` SDK directly, NOT `instructor`, for the primary extraction. The `output_config.format` with `json_schema` provides guaranteed schema compliance via constrained decoding. Instructor's retry-on-validation is a nice-to-have but adds complexity.
    - Cache control on the PDF document block is CRITICAL -- it means the first call caches the PDF tokens, and subsequent calls against the same PDF use cached tokens at 90% discount. This keeps costs under $20 for all 19 models.
    - Import ManufacturerTemplate from templates.base for type hint only (TYPE_CHECKING guard to avoid circular imports).
  </action>

  <action>
    Create four modules that complete the extraction-to-JSON pipeline.

    **1. `backend/src/etl/transform/schema_mapper.py`** -- Maps raw extractions to SpaModel

    Implement `map_to_spa_model(manufacturer: str, series: str, model_name: str, year: int, extractions: dict[str, CategoryExtraction], source_refs: list[SourceReference]) -> SpaModel`:
    - Takes the dict of CategoryExtraction results (one per spec category) from extract_model_specs
    - Assembles a dict matching SpaModel's field structure:
      ```python
      model_data = {
          "manufacturer": manufacturer,
          "series": series,
          "model_name": model_name,
          "year": year,
          "seating_capacity": extractions.get("dimensions", {}).data.get("seating_capacity", 0),
          # Map each category's .data dict to the corresponding SpaModel field
          "jet_pumps": extractions["jet_pumps"].data if "jet_pumps" in extractions else None,
          "circulation_pump": extractions.get("circulation_pump", {}).data,
          # ... etc for all 10 categories + dimensions
          "source_documents": [ref.model_dump() for ref in source_refs],
      }
      ```
    - Calls `SpaModel.model_validate(model_data)` to validate
    - Returns the validated SpaModel
    - On ValidationError: catches it, logs which fields failed, returns None. Also saves the raw model_data dict to a file named `{model}-{year}-RAW.json` in the output directory for debugging.

    Handle gracefully: If a category extraction failed (missing from dict), set that field to a minimal valid default or None (for optional fields like circulation_pump). For required fields (jet_pumps, spa_pak, etc.), raise a clear error about which required category is missing.

    Also handle: `seating_capacity` may come from a dimensions/general extraction. Include it in the extraction prompt for one of the categories (dimensions or a "general" extraction). The schema_mapper should look for it in multiple possible locations in the extracted data.

    **2. `backend/src/etl/transform/validators.py`** -- Post-extraction sanity checks

    Implement `validate_extraction(model_name: str, extractions: dict[str, CategoryExtraction]) -> list[str]`:
    - Returns a list of warning strings (empty = all good)
    - Checks:
      - Range validation: HP values between 0.5 and 10, jet counts between 5 and 200, dimensions between 40 and 150 inches, wattage between 1000 and 6000, seating between 2 and 10
      - Confidence check: Flag any category with confidence == "low"
      - Completeness check: Flag any of the 10 categories that returned no data or all-null fields
      - Cross-model consistency: If all categories have identical data, warn "possible copy-paste extraction error"
    - These are WARNINGS, not blockers. The pipeline logs them but continues.

    **3. `backend/src/etl/output/provenance.py`** -- Builds SourceReference from extraction results

    Implement `build_source_reference(pdf_filename: str, extraction: CategoryExtraction, accessed_date: str = None) -> SourceReference`:
    - Creates a SourceReference (from src.schema.parts) with:
      - `source_type = "pdf"`
      - `document_name = pdf_filename`
      - `page_number = extraction.page_numbers[0]` if page_numbers is non-empty, else None
      - `section = extraction.section_title`
      - `accessed_date = accessed_date or today's date as YYYY-MM-DD string`

    Also implement `build_all_source_refs(pdf_filename: str, extractions: dict[str, CategoryExtraction]) -> list[SourceReference]`:
    - Calls build_source_reference for each extraction
    - Returns deduplicated list (no duplicate page+section combos)

    **4. `backend/src/etl/output/writer.py`** -- Writes validated JSON files

    Implement `write_model_json(spa_model: SpaModel, output_dir: Path = None) -> Path`:
    - Default output_dir: `DATA_OUTPUT_DIR / {manufacturer} / {series_slug}` where series_slug is the series name lowercased with spaces replaced by hyphens (e.g., "880 Series" -> "880-series", "Highlife Collection" -> "highlife", "M Series" -> "m-series")
    - File name: `{model_name_lower}-{year}.json` (e.g., "aspen-2026.json")
    - Creates parent directories if they don't exist
    - Writes `json.dumps(spa_model.model_dump(), indent=2)` -- use model_dump() not model_dump_json() so we can control indentation
    - Returns the Path to the written file
    - Prints: `"Wrote {path} ({size} bytes)"`

    Also implement `write_raw_json(model_name: str, year: int, raw_data: dict, output_dir: Path) -> Path`:
    - For debugging failed validations -- writes the raw extraction dict before schema mapping
    - File name: `{model_name_lower}-{year}-RAW.json`

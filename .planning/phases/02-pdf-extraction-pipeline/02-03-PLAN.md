    **Shared extraction prompt structure (all templates):**
    Every extraction prompt must include these elements:
    ```
    Extract the {category} specifications for the {manufacturer} {model_name} ({series}, {year}) from this owner's manual.

    RULES:
    - Extract ONLY data explicitly stated in the document. Never infer or calculate values.
    - If a value is not present in the document, use null.
    - Include the page number(s) where you found each piece of data.
    - Report your confidence level: "high" if data is clearly stated, "medium" if you had to interpret layout, "low" if uncertain.

    {page_hints from get_page_hints()}

    {category-specific instructions}

    OUTPUT FORMAT:
    The "data" field must contain a JSON object matching this structure:
    {category-specific schema description}
    ```

    **1. `backend/src/etl/templates/sundance.py`** -- Sundance880Template

    Properties:
    - manufacturer_name = "sundance"
    - series_name = "880 Series"
    - models = ["Aspen", "Optima", "Cameo", "Altamar", "Vistamar", "Marin", "Capris"]

    Category-specific prompt additions for `get_extraction_prompt()`:
    - `jet_pumps`: Look for pump count, HP ratings (continuous duty), speed type, frame size. Sundance uses 56 Frame pumps. Look in specifications table. The "data" dict must match JetPumpSpecs structure: `{"pumps": [{"position": N, "horsepower_continuous": X, "speed": "1-speed|2-speed|variable", ...}], "diverter_valves": N, "total_brake_horsepower": X}`
    - `circulation_pump`: Sundance uses a dedicated circ pump. Look for wattage.
    - `spa_pak`: Look for control system name. Sundance uses Advanced Touch Control.
    - `topside_control`: SmartTub System connectivity. Look for control panel features.
    - `jets`: Total jet count per model. Sundance uses Fluidix jets. Extract total count and any jet type breakdown. Data must match JetSpecs: `{"total_jet_count": N, "jet_system_type": "fixed", "jets_by_type": [...]}`
    - `headrests`: Pillow count and type per model.
    - `filters`: MicroClean Ultra filtration system. Look for filter area, quantity.
    - `heater`: Smart Heater, wattage (typically 5500W at 240V for 880 Series).
    - `lighting`: SunGlow LED system. Interior, waterfall, exterior accent lighting.
    - `cover`: Cover dimensions, thickness if listed.
    - Also extract a "general" section in jet_pumps prompt: seating_capacity, dimensions (length, width, height in inches), dry weight, water capacity, voltage, amperage.

    `get_page_hints()`: Return page hint strings based on the PDF analysis report. Format: "Look in pages {N-M} for specification tables." If analysis report found spec comparison tables, reference those specific pages.

    **2. `backend/src/etl/templates/hotspring.py`** -- HotSpringHighlifeTemplate

    Properties:
    - manufacturer_name = "hotspring"
    - series_name = "Highlife Collection"
    - models = ["Grandee", "Envoy", "Aria", "Vanguard", "Sovereign", "Prodigy", "Jetsetter LX", "Jetsetter"]

    Key terminology differences from Sundance:
    - `jet_pumps`: Wavemaster pumps (9000 series, 9200 series). Named pump models, not just HP ratings.
    - `circulation_pump`: SilentFlo 5000 circulation pump (dedicated).
    - `spa_pak`: IQ 2020 control system with FreshWater salt system integration.
    - `topside_control`: IQ 2020 touchscreen with Bluetooth/WiFi.
    - `jets`: Multiple named jet types: Moto-Massage DX, HydroStream, JetStream, Rotary, Directional, Mini. Extract per-type counts and zones. Hot Spring has the most detailed jet breakdown.
    - `filters`: Tri-X filter with no-bypass design. Part number often listed.
    - `heater`: No-Fault heater system.
    - `lighting`: Multi-zone LED with water feature lighting.

    **3. `backend/src/etl/templates/bullfrog.py`** -- BullfrogMSeriesTemplate

    Properties:
    - manufacturer_name = "bullfrog"
    - series_name = "M Series"
    - models = ["M9", "M8", "M7", "M6"]

    CRITICAL DIFFERENCE from other templates:
    - `jets`: Bullfrog uses modular JetPak system. Do NOT extract individual jet types. Instead extract:
      - `jet_system_type`: "modular_jetpak"
      - `jetpak_count`: Number of JetPak bays (slots) in the model
      - `jetpak_options`: Number of available JetPak types (typically 16+)
      - `total_jet_count`: Base jet count without JetPaks (if listed)
      - `max_jet_count`: Maximum jet count with all JetPaks installed (if listed)
      - `therapy_jet_count`: Number of therapy-specific jets
      - `jets_by_type`: Leave empty list -- JetPak configurations are too numerous
    - `jet_pumps`: Bullfrog lists total BHP, not per-pump. Extract total and divide by pump count for per-pump estimate. Note this in extraction prompt.
    - `spa_pak`: Different control system name from Sundance/Hot Spring.
    - `filters`: Simplicity filtration system (different from MicroClean or Tri-X).

    Each template should also define a `GENERAL_FIELDS_PROMPT` constant that asks Claude to extract seating_capacity and dimensions within the first category extraction (jet_pumps), so we get these fields without an extra API call.

  <action>
    Create the main pipeline orchestrator at `backend/src/etl/pipeline.py`. This is the single entry point for running extractions.

    Import all components:
    - Templates: Sundance880Template, HotSpringHighlifeTemplate, BullfrogMSeriesTemplate
    - Extractor: extract_model_specs from extract.claude_extractor
    - Mapper: map_to_spa_model from transform.schema_mapper
    - Validators: validate_extraction from transform.validators
    - Provenance: build_all_source_refs from output.provenance
    - Writer: write_model_json, write_raw_json from output.writer
    - Config: MANUFACTURERS, PDF_STORE_DIR, DATA_OUTPUT_DIR

    Define a template registry:
    ```python
    TEMPLATES = {
        "sundance": Sundance880Template(),
        "hotspring": HotSpringHighlifeTemplate(),
        "bullfrog": BullfrogMSeriesTemplate(),
    }
    ```

    Implement three functions:

    1. `run_model(manufacturer: str, model_name: str, year: int = 2026) -> SpaModel | None`:
       - Looks up template from TEMPLATES dict
       - Looks up PDF path from config: `PDF_STORE_DIR / manufacturer / MANUFACTURERS[manufacturer]["pdf_filename"]`
       - Validates PDF exists, raises FileNotFoundError if not
       - Calls `extract_model_specs(pdf_path, template, model_name)` to get all category extractions
       - Calls `validate_extraction(model_name, extractions)` -- prints any warnings
       - Calls `build_all_source_refs(pdf_path.name, extractions)` for provenance
       - Calls `map_to_spa_model(manufacturer, series, model_name, year, extractions, source_refs)`
       - If mapping succeeds: calls `write_model_json(spa_model)` and returns spa_model
       - If mapping fails (returns None): calls `write_raw_json(model_name, year, raw_data, output_dir)` for debugging, returns None
       - Prints summary: model name, categories extracted, warnings, output file path

    2. `run_manufacturer(manufacturer: str, year: int = 2026) -> list[SpaModel]`:
       - Looks up model list from `MANUFACTURERS[manufacturer]["models"]`
       - Calls `run_model()` for each model in sequence
       - Returns list of successfully extracted SpaModel instances
       - Prints summary: N of M models extracted successfully, any failures listed

    3. `run_extraction(year: int = 2026, manufacturers: list[str] | None = None) -> dict[str, list[SpaModel]]`:
       - If manufacturers is None, uses all keys from MANUFACTURERS
       - Calls `run_manufacturer()` for each
       - Returns dict mapping manufacturer to list of SpaModels
       - Prints grand summary: total models, successes, failures, warnings

    Add a `__main__` block so the pipeline can be invoked from CLI:
    ```python
    if __name__ == "__main__":
        import sys
        if len(sys.argv) > 1:
            manufacturer = sys.argv[1]
            model_name = sys.argv[2] if len(sys.argv) > 2 else None
            if model_name:
                run_model(manufacturer, model_name)
            else:
                run_manufacturer(manufacturer)
        else:
            run_extraction()
    ```

    Usage examples (to be documented in docstring):
    - `uv run python -m src.etl.pipeline` -- extract all manufacturers
    - `uv run python -m src.etl.pipeline sundance` -- extract all Sundance models
    - `uv run python -m src.etl.pipeline sundance Aspen` -- extract Sundance Aspen only

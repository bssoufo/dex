<task type="auto">
  <name>Task 2: Add /query/stream SSE endpoint to app.py</name>
  <files>backend/src/api/app.py</files>
  <action>
Add a new `POST /query/stream` endpoint to `app.py` that returns a `StreamingResponse` with `media_type="text/event-stream"`. The endpoint:

1. Accepts the same `QueryRequest` body as `/query` (question + optional conversation_id).
2. Returns a `StreamingResponse` that yields SSE-formatted events.
3. Uses `_agent.astream()` with `stream_mode="updates"` and the thread config for conversation continuity.

SSE event format (each event is `event: {type}\ndata: {json}\n\n`):
- `event: metadata` -- Sent first. Data: `{"conversation_id": "<uuid>"}`.
- `event: token` -- Sent for each node output that contains message content. Data: `{"content": "<text>", "node": "<node_name>"}`. Extract content from the messages in each streamed chunk. Only emit token events for messages that have non-empty string content. Handle Gemini's list-of-blocks content format (same normalization as existing /query endpoint).
- `event: done` -- Sent after astream completes. Data: `{"status": "complete"}`.
- `event: validation` -- Sent after done. Run `validate_response()` on the accumulated state and send any warnings. Data: `{"warnings": ["...", ...]}` or `{"warnings": []}`.

Important implementation details:
- Import `StreamingResponse` from `fastapi.responses`.
- Import `json` at the top of the file.
- Generate/reuse conversation_id the same way as the existing `/query` endpoint.
- Accumulate all messages from the astream into a list so the validator can run on the complete state after streaming finishes.
- Set response headers: `Cache-Control: no-cache`, `X-Accel-Buffering: no` (prevents proxy buffering).
- Guard against `_agent is None` with 503 just like the existing endpoint.
- The async generator function should be defined inside the endpoint function (closure over request params).
- To build the full state for the validator, collect messages into a list during streaming. After the loop, call `validate_response({"messages": accumulated_messages})`.
- For extracting content from node outputs: iterate `chunk.items()` to get `(node_name, node_output)`, then check `node_output.get("messages", [])`. For each message with a `content` attribute, normalize it (handle list-of-blocks from Gemini the same way the existing endpoint does).

Keep the existing `/query` endpoint completely unchanged.
